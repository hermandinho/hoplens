# Changelog

Per-package changes land in `packages/<name>/CHANGELOG.md`, generated by
[Changesets](https://github.com/changesets/changesets) from the next release
onwards. This file tracks milestones at the project level.

## 0.1.0 — Initial release

First public cut of Hoplens — a dev-only request-journey visualizer for
Node.js backends, starting with Next.js.

### Packages

- **`hoplens`** — meta-package. `npm i -D hoplens` and you get the CLI, the
  Next adapter, and the runtime.
- **`@hoplens/cli`** — `hoplens init | doctor | remove`.
- **`@hoplens/next`** — `withHoplens()` config wrap, Next 15.3+ route scanner,
  instrumentation hook.
- **`@hoplens/core`** — framework-agnostic capture, OTel bridge, UI server,
  source maps, redactor.
- **`@hoplens/schema`** — static Zod reader (interprets `z.*` without
  executing).
- **`@hoplens/transform`** — TypeScript AST source transform that wraps
  exported functions as traced wrappers without moving a single line.
- **`@hoplens/ui`** — Preact + Vite single-HTML dashboard served at
  `/__hoplens`.

### What you get

- `npx hoplens init` wires `withHoplens()` into `next.config.*` and the
  Hoplens block into `instrumentation.register()`.
- `next dev` → open `/__hoplens` → see every request's full hop-by-hop
  journey, errors pinned to the exact `.ts` line, built-in request builder
  that pre-fills bodies from Zod schemas.
- Playwright-tested at desktop / tablet / mobile breakpoints.
- Dev-only guaranteed: `next build` ships zero Hoplens code into the server
  bundle.
- Coexists with existing OpenTelemetry setups — Hoplens attaches as a reader,
  it doesn't replace your provider.
